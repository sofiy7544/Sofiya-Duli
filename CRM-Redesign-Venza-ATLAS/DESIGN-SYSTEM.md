# Дизайн-система CRM — On Top Property × RealtorsOS

Версия 1.0 · собрано по реальным токенам превью (`src/styles/themes.css`), проверено гейтом контраста (`tools/contrast-gate.py` → `AA FAILS: 0`) и правилами скила UI UX Pro Max.

Документ описывает то, что уже реализовано в кликабельном превью, и правила, по которым дописываются новые экраны. Это не пожелания, а спецификация: каждое значение есть в коде.

---

## 1. Темы и цвет

Три темы живут на одном наборе CSS-переменных. **ATLAS — стандартная.** «Светлая» и «Тёмная» удалены по решению заказчика; сохранённые значения этих тем мягко мигрируют в ATLAS. Компонент не знает, в какой он теме: он использует токен. Тему задаёт `data-theme` на `<html>`, семейство композиции — `data-family` (`classic` / `venza` / `atlas`).

### 1.1 Смысловые токены

| Токен | Назначение |
|---|---|
| `--background` | фон страницы |
| `--surface`, `--surface-2` | карточки и вложенные поверхности |
| `--foreground`, `--muted-foreground` | основной и второстепенный текст |
| `--primary`, `--primary-foreground`, `--primary-soft` | действие, текст на нём, мягкая подложка |
| `--accent`, `--accent-foreground` | акцент темы (у Venza — золото) |
| `--border`, `--input`, `--ring` | границы, поля, фокус |
| `--success/--warning/--danger/--info` | заливки статусов |
| `--success-text/--warning-text/--danger-text/--info-text` | те же статусы **для текста** |

**Правило статусов.** Заливка и текст — разные токены. Жёлтый и зелёный, читаемые как плашка, не читаются как текст. Для подписи всегда `*-text`.

### 1.2 Палитры (ключевые значения)

| Тема | background | surface | primary | акцент |
|---|---|---|---|---|
| Venza | `#F7F4EC` | `#FFFEFB` | `#344A39` лесной | `#C6A568` золото |
| ATLAS (стандарт) | `#F5F7FA` | `#FFFFFF` | `#235F91` сталь | `#D0A34A` |
| Сепия | `#F2EDE3` | `#F9F6F0` | `#A6541D` | `#B85227` |

Коррекции ради контраста: сепия `#B65C20 → #A6541D`, ATLAS danger `#D45656 → #C94848`, Venza muted `#757B75 → #6A6F6A`.

### 1.3 Контраст

- Текст и фон — не ниже **4.5:1**, включая приглушённый текст и статусные подписи.
- Проверка обязательна при любом изменении цвета: `python3 tools/contrast-gate.py` должен дать `AA FAILS: 0` (70 пар × 5 палитр).
- Статус никогда не передаётся только цветом: рядом всегда текст, а часто ещё и точка либо иконка.

### 1.4 Слои, тени, стекло

- **Тени:** `--shadow-soft` (карточка в покое), `--shadow-lift` (перетаскивание, листы, всплывающие панели), `--shadow-fab`. Две системы теней не смешиваем.
- **Стекло** (`backdrop-filter`) — только навигация, плавающие контролы и оверлеи. Контент всегда плотный: на стекле падает читаемость текста.
- Есть запасной вариант: при отсутствии `backdrop-filter` стекло становится сплошной поверхностью.
- Градиенты — только в бренде и медиа. В интерфейсе плоские поверхности и одна линия границы.

## 2. Типографика

| Семейство | Заголовки | Интерфейс | Цифры |
|---|---|---|---|
| Venza | Playfair Display 600 | Inter | Playfair, табличные |
| ATLAS | Inter 650–700, плотный трекинг | Inter 15px | Inter, `tabular-nums` |
| Classic | Inter | Inter | Inter |

**Шкала** (класс → размер/интерлиньяж): `t-hero` 34/38 · `t-h1` 30/34 · `t-h2` 22/28 · `t-h3` 17/23 · базовый текст 15–16/22 · `t-caption` 13/18 · `t-micro` 11/15. В ATLAS вся шкала на шаг плотнее (`t-hero` 28/34).

**Правила:**
- Один `h1` на страницу. Заголовок страницы и заголовок в шапке не дублируются.
- Строка текста — не длиннее 68 символов (`max-w-[68ch]` в описаниях).
- Все суммы, даты и счётчики — табличными цифрами, иначе числа «прыгают» при обновлении.
- На мобильном поля ввода не мельче 16px, иначе Safari зумит экран при фокусе.

## 3. Сетка и пространство

- **Шаг 4pt**, ключевые отступы кратны 8: 8 / 12 / 16 / 20 / 24 / 32.
- **Скругления:** `--radius-control` 14px, `--radius-card` 18px, `--radius-sheet` 24px. В ATLAS всё на 2–4px меньше: плотнее и строже.
- **Поля страницы:** мобильный 16px, Venza на десктопе 40px, ATLAS 24px.
- **Ширина контента:** Venza до 1120px (читаемость), ATLAS до 1480px (плотность данных).
- **Сайдбар:** ATLAS 232px тёмный, Venza 240px светлый, classic — карточка.
- **Отступ под нижнюю навигацию:** `pb-mobile-nav`, иначе последняя строка списка уезжает под панель.

## 4. Компоненты

### 4.1 Кнопки

| Вариант | Когда |
|---|---|
| `default` | одно главное действие на экран |
| `soft` | частое, но не главное действие |
| `outline` | второстепенное, рядом с главным |
| `ghost` | действия в строках и шапках |
| `destructive` | удаление, только после подтверждения |
| `link` | переход внутри текста |

Высота 48px на мобильном, 44px на десктопе, иконка-кнопка не меньше 44×44. У каждой иконки-кнопки есть `aria-label`. Нажатие даёт масштаб 0.97 за 100мс. Состояние загрузки встроено в кнопку (`loading`), надпись не заменяется на спиннер, чтобы ширина не прыгала.

### 4.2 Поля и формы

- Подпись всегда видима, связана с полем через `id`. Плейсхолдер не заменяет подпись.
- Фокус: цвет границы плюс мягкое кольцо `0 0 0 4px primary/12`. Убирать контур фокуса нельзя ни при каких условиях, включая модальные окна.
- Ошибка: `aria-invalid`, `role="alert"`, текст под полем. Поле не «трясётся», сообщение появляется мягко.
- Проверка — после первой попытки отправки, затем на каждое изменение. До первой попытки поле не краснеет.
- Клавиатура под тип данных: `inputMode="tel"` для телефона, `numeric` для сумм, `email` для почты.
- Нативные поля даты и времени ограничены по ширине (`min-width: 0`), иначе на iPhone они распирают лист.

### 4.3 Таблицы и списки

- **Без зебры.** Разделитель — линия `border/70`. Зебра спорит с подсветкой строки и статусными плашками.
- Строка: hover — подложка `surface-2/60`, выбранная — кольцо `primary`.
- Заголовки колонок 12,5px, приглушённые, `scope="col"`.
- Числовые колонки выровнены вправо, табличными цифрами.
- Горизонтальная прокрутка только внутри таблицы, страница не ездит.
- На мобильном таблица превращается в список карточек, а не ужимается.

### 4.4 Карточка лида в канбане

Анатомия сверху вниз: аватар-монограмма и имя, значок приоритета, бюджет, источник и ответственный, полоса срочности. Полоса красная при просрочке, янтарная на сегодня, серая в остальных случаях. Внутри карточки не больше двух акцентов, иначе доска рябит.

**Перетаскивание:** подъём (наклон 1,2°, увеличение 1,02, тень `lift`), подсветка колонки-цели пунктиром, посадка за 180мс. Перетаскивание не может быть единственным способом: на карточке есть кнопка «…» со списком этапов и поддержкой клавиатуры.

Недопустимые переходы видны, но объяснены: «Сделка» доступна только из «Переговоров», «Проиграно» требует причину.

### 4.5 Листы, модальные окна, подтверждения

- Мобильный — лист снизу со свайпом вниз, десктоп — панель справа или окно по центру.
- Разрушительное действие всегда через подтверждение, фокус по умолчанию на «Отмена».
- Esc закрывает, фокус возвращается на кнопку-источник.

### 4.6 Состояния данных

Четыре состояния у каждого экрана: загрузка, данные, пусто, ошибка.
- **Skeleton** повторяет форму будущего контента, а не крутится спиннером.
- **Пусто** — иконка, заголовок, одно предложение и одно действие.
- **Ошибка** — что случилось и кнопка «Повторить». Навигация остаётся доступной.
- В превью все четыре переключаются в панели для проверки вёрстки.

### 4.7 Дата и время

- Выбор времени — системным полем `datetime-local` (или `time`). На iPhone это тот же барабан, что в будильнике, на Android — системные часы. Свой «красивый» выбор хуже: не знает про 12/24 часа, локаль и VoiceOver.
- Рядом с полем — фишки-пресеты: «Через час», «Сегодня, 18:00», «Завтра, 10:00», «Завтра, 18:00», «Через 3 дня», «Через неделю». Пресеты закрывают обычный случай в один тап, поле — всё остальное.
- Пресет, который уже прошёл, не показывается: «Сегодня, 18:00» в 22:30 создавал задачу сразу просроченной. Пресеты и умолчание считаются от текущего времени (`lib/due.ts`).
- Под выбором — подпись словами: «Напомню завтра в 10:00». Человек проверяет смысл, а не формат даты.
- **Обязательное время помечается `required`.** У необязательного поля системный барабан на iPhone показывает кнопку «Сбросить», и она очищает значение. Для показа или срока задачи пустое время бессмысленно: `required` эту кнопку убирает. Единственное поле, где она уместна и оставлена, — «перезвонить» в итоге звонка: звонок бывает и без перезвона.
- **Пустое время — состояние, а не сбой.** Если поле всё-таки очистили, экран говорит «Выберите время показа» и гасит кнопку действия. Раньше лист показа пытался создать событие из недействительной даты и выдавал английское `Invalid time value`.

### 4.8 Ряд, который листается вбок

- **Край растворяется, а не обрывается.** Фишки этапов обрезались ровно по краю экрана и читались как целые — понять, что ряд продолжается, было неоткуда. Затухание в 36 px снимает «стену»: надрезанная фишка видна надрезанной.
- **Подсказка честная.** Затухание включается только там, где действительно есть что листать: нет переполнения — нет затухания (на широком экране его не видно вовсе); долистали до конца — гаснет с той стороны, где листать больше нечего. Иначе это украшение, которое врёт.
- **Считает не React.** Состояние пишется в `data-fade` на самом узле (`lib/use-hscroll.ts`), рисует его CSS. Ни один кадр прокрутки не проходит через перерисовку.
- **Ref-функция, не эффект.** Ряд появляется не сразу — сначала скелетон; эффект с пустыми зависимостями успевал отработать, когда узла ещё не было, и больше не повторялся.
- **Полоска-ползунок под коротким рядом.** Дорожка в 1 cm по центру (`--hs-track`), высота 3 px. Затухание объясняет, что край не конец; полоска показывает, сколько ещё осталось и где вы сейчас: ширина бегунка — видимая доля ряда, положение — насколько отлистали. Появляется по тому же правилу: нет переполнения — нет полоски.
- **Только там, где её видно.** Под рядом этапов полоска сразу под фишками. Под канбаном её нет намеренно: колонки высокие, низ ряда уходит за экран, и подсказка оказалась бы там, куда никто не смотрит — канбану достаточно затухания.
- Применено к ряду этапов на телефоне (затухание + полоска), канбану сделок и канбану лидов (только затухание). Широкие таблицы внутри карточек так не помечаются: у них есть рамка, и маска съела бы её край — там нужен приём с тенью, не с затуханием.

### 4.9 Шапка экрана

- Слева — знак агентства, одинаковый на всех экранах CRM; справа — действия экрана, «молния» (быстрый захват) и поиск. На карточках слева от знака стоит стрелка «Назад».
- Знак только на мобильном: на десктопе бренд уже стоит в сайдбаре, и второй знак был бы дублем.
- Знак без словесной части: справа помещается до четырёх кнопок, и при ширине 360–390px название обрезалось бы на каждом экране по-разному.
- Размер знака: 38px, на «Сегодня» — 28px, потому что там под шапкой ещё дата и крупное приветствие.
- Знак — ссылка на «Сегодня» с зоной нажатия 44px; на самой «Сегодня» это просто знак, без ссылки.

## 5. Микровзаимодействия и скорость

### 5.1 Тайминги

| Действие | Время | Кривая |
|---|---|---|
| Нажатие | 80–100мс | standard |
| Наведение, таб | 140–160мс | standard |
| Строка списка | 160мс | standard |
| Переход страницы | 200мс | emphasized |
| Лист снизу | 240мс | emphasized |
| Skeleton | 1100мс | ease-in-out |

Анимируются только `transform` и `opacity`. Всё уважает `prefers-reduced-motion`: движение выключается, остаётся мгновенная смена состояния.

### 5.2 Меньше кликов

| Действие | Сейчас |
|---|---|
| Новый лид | кнопка «+» → форма из двух полей, клиент и лид создаются вместе |
| Смена этапа | перетаскивание, либо «…» на карточке, либо бейдж этапа в карточке лида |
| Звонок с результатом | кнопка «Звонок» → выбор результата, заметка, перезвон. Перезвон сразу создаёт задачу |
| Показ | из карточки лида, клиент уже подставлен, объект предложен по интересу |
| Сделка | «Готов купить» переводит лид в «Переговоры» и открывает форму сделки |
| Отмена ошибки | тост с «Отменить» у смены этапа, выполнения задачи и архивации |

### 5.3 Клавиатура

- Горячие клавиши как в CRM: ⌘K поиск · ⌘N клиент · ⌘L лид · ⌘O объект · ⌘S событие · Shift+? справка. В полях ввода перехватываются только комбинации с ⌘/Ctrl — иначе «?» в тексте заметки открывал бы справку.

- `⌘K` / `Ctrl+K` — поиск по лидам, клиентам и объектам, стрелки и Enter для выбора.
- `Esc` — закрыть лист, окно, поиск.
- Стрелки — переключение сегментов, выбор в списке результатов.
- Табуляция — видимый фокус на каждом элементе, включая элементы внутри модальных окон.

### 5.4 Правила плотной работы

Проверено прогоном рабочего месяца трёх риелторов (телефон, установленное приложение, компьютер). Правила, которые из него выросли:

| Правило | Почему |
|---|---|
| Тост никогда не перекрывает основное действие | Плашка висит 3–5 с и на телефоне лежала ровно на кнопке «+»: нажатие уходило в неё |
| Результат действия виден или доступен из тоста | Срок новой задачи по умолчанию не сегодняшний — задача попадала во вкладку, которую никто не открыл. У тоста есть «Показать»: список сам открывает нужную вкладку и подсвечивает строку |
| Возврат из карточки — на то же место списка | Списки длинные (полсотни клиентов). Позиция запоминается по шагу истории и восстанавливается, когда список дорисовался; ручная прокрутка отменяет восстановление |
| Анимация уступает человеку | Почта на входе впечатывается сама, но замолкает при первом касании поля: иначе она переписывала ввод и уводила фокус |
| Индикатор говорит правду | Красная точка у колокольчика — только когда есть просрочки, ближайшие показы или лиды без ответственного |
| Поиск не зависит от раскладки | «Ницца» и «Эз» находят Nice и Èze: словарь синонимов района, снятая диакритика, ё → е. В CRM это `search_vector` с синонимами |
| Ряд вкладок прокручивается | Четыре вкладки со счётчиками не помещались в 360 px, последняя обрезалась |

## 6. Раскладки ключевых экранов

### 6.1 «Сегодня»

- **Venza, мобильный:** тон шапки по времени суток → приветствие → три показателя (задачи, показы, новые лиды) → блок просрочки → повестка дня с временем засечками → новые лиды → лента «Недавно».
- **ATLAS, десктоп:** пять KPI в ряд → слева воронка по этапам и «Последние действия», справа расписание и просрочка.
- Полоса выручки появляется, только когда есть закрытые сделки.

### 6.2 Лиды

- **Мобильный:** чипы этапов со счётчиками → список карточек → «…» открывает действия.
- **Десктоп:** канбан с колонками этапов, суммой бюджетов в шапке колонки и колонкой «Проиграно» как зоной сброса. Для администратора — режим выбора и массовые действия.
- Фильтры — лист: приоритет, источник, ответственный, срочность, с кнопками «Сбросить» и «Показать N».

### 6.3 Карточка клиента и лида

- **Venza:** крупная монограмма, имя, этап и приоритет, четыре быстрых действия, вкладки «Инфо / Задачи / История», липкая панель с главным действием.
- **ATLAS, десктоп:** четыре колонки — список других лидов, профиль и запрос, история с заметками, справа следующее действие, объект и задачи.

## 7. Чек-лист внедрения

**Фундамент**
1. Подключить токены и провайдер тем из `02_phase2-kit`, прогнать гейт контраста.
2. Заменить «мёртвые» классы (`bg-card`, `text-destructive`, `h-4.5`) на токены.
3. Свести две системы теней к `soft` / `lift` / `fab`.
4. Подключить шрифты через `next/font`, убрать неопределённые переменные шрифтов.

**Компоненты**
5. Кнопка: варианты и `loading` внутри компонента.
6. Поля: видимая подпись, `aria-invalid`, `role="alert"`, ограничение ширины нативных дат и времени.
7. Один `SegmentedControl` вместо всех сегментированных переключателей.
8. Один `Sheet` для листов и боковых панелей, `ConfirmDialog` для разрушительных действий.
9. Skeleton по форме контента, единые пустые состояния и ошибки.

**Экраны**
10. Один `h1` на страницу, разгрузить мобильную шапку.

## 8. Что осознанно не сделано

- **Без бейджей безопасности** (SOC2, «256-bit») — без реальных сертификатов это ложное заявление.
- **Без градиентных «неоновых» акцентов в рабочих экранах** — они мешают читать плотные данные и стареют за сезон.
- **Без плотной анимации в списках** — движение только там, где сообщает о результате действия.
