# Сверка дизайна с кодом CRM: что переносится и как

Вопрос был простой: отдадим ли мы дизайн и ляжет ли он на кнопки, которые уже есть в коде. Короткий ответ — да, потому что превью с самого начала строилось на компонентах и маршрутах из вашего handoff, а не рисовалось отдельно. Ниже подробности и честные места, где разработчику придётся дописать руками.

---

## 1. Экраны: маршрут в маршрут

| Экран превью | Маршрут в CRM | Состояние |
|---|---|---|
| Вход | `app/login/page.tsx` | Готов, заменяет текущий экран целиком |
| Сегодня | `/today` (легаси `/dashboard`) | Готов |
| Лиды и воронка | `/leads` (легаси `/pipeline`, `/pool`) | Готов, включая канбан и мобильный список |
| Карточка лида | `/leads/[id]` | Готов, панели как в CRM |
| Клиенты | `/clients` (легаси `/contacts`) | Готов |
| Карточка клиента | `/clients/[id]` | Готов |
| Объекты | `/properties` (легаси `/inventory`) | Готов |
| Карточка объекта | `/properties/[id]` | Готов |
| Задачи | `/tasks` | Готов |
| Календарь | `/calendar` | Готов: месяц, неделя, день, список |
| Сделки | `/deals`, `/deals/new`, `/deals/[id]` | Готов |
| Настройки | `/settings` | Частично: оформление готово, подразделы — заглушки |
| Заметки, Отчёты, Команда, Коммуникации | `/notes`, `/reports`, `/team`, `/inbox` | Заглушки с честным текстом, дизайн в следующей итерации |

Легаси-адреса перенаправляются так же, как в CRM, поэтому старые ссылки в письмах и закладках не ломаются.

## 2. Кнопки и компоненты: что делать с существующим кодом

В handoff зафиксировано, что кнопки в CRM разъехались: часть экранов использует `ui/button.tsx`, часть — сырые `<button>` со своими радиусами (`rounded-lg` против `rounded-xl`), есть отдельные `IconBtn` по 32px, свои пилюли и сегментированные переключатели, у полей ввода четыре разных стиля фокуса.

| Компонент превью | Что в CRM | Действие |
|---|---|---|
| `ui/button.tsx` (варианты + `loading`) | `ui/button.tsx` без `loading`, плюс сырые кнопки | Заменить файл, затем перевести сырые кнопки на компонент |
| `ui/field.tsx` | `ui/input.tsx`, `textarea`, свои обёртки | Заменить, привести к одной подписи и одному фокусу |
| `ui/segmented.tsx` | ~11 разных сегментированных контролов | Один компонент вместо всех |
| `ui/sheet.tsx` | `ui/dialog.tsx` + `sheet` | Общий лист: снизу на телефоне, панель на десктопе |
| `ConfirmDialog` | подтверждения разбросаны | Один диалог на все разрушительные действия |
| `ui/badge.tsx` | статусы разными способами | Заливка и текст статуса разделены токенами |
| `ui/skeleton.tsx`, `EmptyState`, `ErrorState` | частично | Четыре состояния у каждого экрана |
| `ui/toast.tsx` | sonner | API совпадает, включая «Отменить» |

**Важно:** публичные props сохранены, поэтому вызовы вида `<Button variant="outline" size="sm">` продолжают работать. Разница только в добавленных возможностях (`loading`, вариант `soft`).

## 3. Что уже соответствует правилам самой CRM

- **Правила воронки:** «Сделка» только из «Переговоров», «Проиграно» требует причину.
- **Побочные эффекты сделок:** завершение переводит лид в «Сделка», отмена — в «Проиграно» с причиной.
- **Права:** платежи, удаление сделки и смена ответственного — ADMIN и MANAGER; «Команда» и «Отчёты» — ADMIN; «Коммуникации» по флагу `NEXT_PUBLIC_INTEGRATIONS_ENABLED`.
- **Формы:** проверки повторяют серверные (телефон 6–32 символа, пароль 8–128, комиссия 0–100, сумма больше нуля).
- **Данные:** `lib/mock/api.ts` повторяет формы ответов `lib/api.ts`, у каждой функции в комментарии указан endpoint.

---

## 4. Что разработчику придётся сделать руками

1. Заменить `lib/mock/*` на реальные запросы (сигнатуры и формы ответов уже совпадают).
2. `PropertyMedia` → `BlurImage` с медиа из `/api/uploads`.
3. Строки интерфейса → next-intl (пять локалей).
4. Hash-роутер превью → App Router; пути совпадают.
5. `stores/ui-store.ts` вместо `components/shell/ui-state.ts`.
6. Кобрендинг входа: публичный эндпоинт `GET /api/tenants/resolve?domain=`, не раскрывающий, существует ли пользователь.
7. Фон входа положить в `public/` и отдавать отдельным файлом, а не инлайном.
8. Панель превью не переносить — она только для ревью.

## 5. Мобильная оптимизация: что исправлено в этой итерации

- **Убран серый «резиновый» отскок** при смахивании вбок: странице запрещена горизонтальная прокрутка и переброс жеста, фон подложки теперь цвета темы, а не системный серый.
- **Жесты разделены:** страница тянется только по вертикали, горизонтальные ленты (канбан, чипы этапов, галерея, таблицы) прокручиваются сами и не «дёргают» страницу.
- **Цели нажатия доведены до 44px:** сердце «в подборку», стрелка «открыть объект», вкладки, сегменты приоритета, бейдж этапа, текстовые ссылки внутри строк.
- **Нативные поля даты и времени** больше не распирают листы в Safari.
- **Проверено автоматически** на 320 и 390px по всем экранам: горизонтального переполнения нет, элементов без подписи нет, текста мельче 11px нет.

---

## 6. Порядок передачи

1. Отдать разработчику архив: `01_preview/source` (дизайн-эталон), `02_phase2-kit` (токены, темы, навигация) и `DESIGN-SYSTEM.md`.
2. Внедрять по чек-листу из дизайн-системы: фундамент → компоненты → экраны → проверка.
3. После фундамента прогнать `tools/contrast-gate.py`: должно быть `AA FAILS: 0`.
4. Экраны переносить по одному, сверяя с превью: оно открывается в браузере и работает офлайн.
